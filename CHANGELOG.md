# Changelog

## [Unreleased]

### Added

- Initial release: `Scry.Engine.ArangoDB` -- a real `Scry.Core.EngineBehaviour` implementation over ArangoDB, via `arangox`. Replaces `scry_docgraph`'s own reference implementation (`Scry.DocGraph.Executor`, one in-memory space serving both document-tree and graph-node roles at once, plus a separate in-memory adjacency map) with genuine collection-and-AQL-traversal-backed `DEEP`/`PARENT`/`SIBLINGS`/`ANCESTORS` *and* `VIA`/`PATH` execution, each independently nestable inside the other -- the document+graph composite kind's first real adapter, closing the one remaining kind package with a real fused executor and zero real-backend validation (`scry_docgraph`'s own moduledoc names ArangoDB directly as the deferred candidate). No roadmap-named package existed for this at all, so this is a fresh design, not a correction.
  **Driver**: `arangox`, the community-preferred ArangoDB client, `DBConnection`-based, not a compile-time macro-based connection module the way `instream`/`snap` were -- ~17 months since its last release, real but nowhere near the multi-year abandonment already confirmed for other corrected drivers this round, a genuine deliberate choice.
  **Two real driver findings**: `arangox`'s own default client (`Arangox.VelocyClient`) needs a `:velocy` peer dependency neither it nor this package requires automatically, confirmed directly (`Conn.open/1` always forces `client: Arangox.MintClient` instead); and a query-level failure during cursor enumeration *raises* rather than returning `{:error, _}`, confirmed directly querying a nonexistent collection (`Conn.query/3` always wraps the transaction in `rescue`).
  **Document collection-per-tree-key, joined with `__`**: the identical convention `scry_engine_mongodb_driver`/`scry_engine_couchdb` already established, since ArangoDB disallows a literal `.` in collection names (confirmed directly, the same restriction found for CouchDB).
  **Edge collections, one per `VIA` edge name, `_key` doubles as the reference's own required `"id"`**: unlike the pure-document adapters (where the driver's own identity field is pure noise, stripped), `scry_docgraph`'s own reference `Conn` requires a graph-participating row to carry a real, user-visible `"id"` -- so ArangoDB's own `_key` is renamed to `"id"` rather than stripped, the same real thing confirmed by the reference's own contract.
  **`VIA`'s own traversal**: AQL's variable-length traversal doesn't enforce simple-path semantics by default either (the identical divergence found for Cypher), but ArangoDB has a native, plugin-free fix (`OPTIONS { uniqueVertices: "path" }`, confirmed directly against a real cyclic graph) -- no manual `WHERE ALL(...)` needed, unlike Neo4j. `opts.shortest` is not translated into `SHORTEST_PATH`/`K_SHORTEST_PATHS` (both name a single target, not "shortest to every reachable node") -- every simple path is fetched and `keep_shortest/1`, a direct port of the reference's own function, groups by end-vertex and keeps every tied path client-side, giving **exact tie-parity with the reference**, unlike `scry_engine_neo4j`'s own stated `SHORTEST 1` divergence.
  **A missing document collection is an error; a missing edge collection is empty**: confirmed directly, matching the reference's own strict per-source behavior for documents (the same divergence-from-Neo4j/MongoDB `scry_engine_couchdb` already documents) while a `VIA` edge collection that was never created gracefully means no edge of that name exists anywhere, matching the reference's own adjacency-map behavior.
  **Parity tested against the reference**: AGENTS.md's own "Parity between multiple implementations" rule applied directly -- `scry_docgraph`'s own `Scry.DocGraphTest` fixture reused verbatim, parsed once via `Scry.DocGraph.parse/1`, run against both a real ArangoDB container and the reference's own in-memory `Conn`.
